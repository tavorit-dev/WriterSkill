# 一、产品定位

# 天工 · Tiangong

## Intelligent Writing & Content Crafting

让想法更有结构，让表达更有质量，让内容更有生命力。


核心定位

一个能够理解创作意图、辅助内容规划、提供写作指导、优化文章结构、推荐视觉素材并完成内容排版的通用写作 Skill。

重点服务以下场景：

| 场景   | 主要用途              |
| ---- | ----------------- |
| 技术写作 | 技术博客、技术原理、架构设计、教程 |
| 知识创作 | 科普文章、知识分享、学习笔记    |
| 内容运营 | 公众号、社交媒体、专题内容     |
| 产品文档 | PRD、产品介绍、使用指南     |
| 商业写作 | 行业分析、项目介绍、方案报告    |
| 日常写作 | 随笔、总结、观点表达        |

其中，技术写作和知识创作为第一阶段的重点场景。

# 二、核心能力设计

核心能力划分为六个模块。

01\. 构思与选题（Ideation）

帮助用户从一个简单想法发展成完整的写作方向。

- 主题分析与选题拓展
- 写作目的和目标读者分析
- 核心观点提炼
- 内容角度和差异化建议
- 写作素材收集建议

02\. 结构与布局（Structure）

解决文章如何组织、如何展开的问题。

- 文章大纲生成
- 章节组织与层级规划
- 论证逻辑检查
- 段落顺序调整
- 开头、正文、结尾的布局建议
- 不同文章类型的结构模板

03\. 写作指导（Writing Guidance）

不只是生成内容，更重要的是在写作过程中提供指导。

- 根据当前段落提供写作提示
- 提示需要补充的论据和案例
- 识别表达不清晰的问题
- 提醒内容缺失和逻辑断层
- 推荐示例、类比和解释方式
- 提供不同表达方式

04\. 图片与视觉设计（Visual Design）

让文章不仅有内容，也有良好的视觉表达。

- 分析文章中的图片需求
- 推荐插图位置
- 生成图片描述和绘图 Prompt
- 推荐架构图、流程图、示意图
- 图片与文字的关联性检查
- 图片说明、图注和 Alt Text
- 图片风格统一性建议

05\. 内容编辑与质量评审（Editing & Review）

对已有内容进行专业评审，而不是简单改写。

- 结构完整性检查
- 逻辑一致性检查
- 内容准确性和事实核查
- 语言流畅度优化
- 冗余内容识别
- AI 痕迹和模板化表达检查
- 多轮修改与版本对比

06\. 排版与发布（Publishing）

根据最终发布平台调整内容格式。

- Markdown 排版
- 公众号排版建议
- 标题、摘要和导语优化
- 代码块、表格、引用格式
- 图片占位与资源引用
- HTML 等格式转换

# 三、最重要的设计：写作工作流

六项能力不应该是孤立的工具，而应该组成一个可以随时介入、允许反复迭代的写作流程。

采用以下工作流：

## 天工写作流程

1. 确定创作意图

   理解主题、目标读者、写作目的和发布场景。
2. 规划内容结构

   输出文章大纲、章节安排、核心观点和论证路线。
3. 逐步完成写作

   按章节或段落展开，提供写作提示、案例和素材建议。
4. 补充视觉内容

   识别插图需求，生成图片建议、图表方案和图片 Prompt。
5. 质量评审与修改

   从结构、逻辑、事实、表达、可读性等方面进行检查。
6. 排版与交付

   输出适配目标平台的最终内容。

工作流不是强制线性的。用户可以从任意阶段开始，也可以反复返回修改。

这里有一个很重要的产品设计原则：

天工应该支持三种工作模式，而不是要求用户每次都从头开始。

| 模式   | 用户行为       | Skill 行为      |
| ---- | ---------- | ------------- |
| 引导创作 | 我有一个想法，帮我写 | 逐步引导完成创作      |
| 协作写作 | 我已经写了一部分   | 分析上下文，提供下一步建议 |
| 内容优化 | 帮我评审这篇文章   | 直接进入评审、修改和优化  |

例如：

- 「我想写一篇关于 Redis 渐进式 Rehash 的文章」→ 引导创作。
- 「这一章节不知道怎么展开」→ 协作写作。
- 「帮我评审这篇技术文章」→ 内容优化。

# 四、图片与视觉内容：建议作为特色能力

这是天工值得重点投入的方向。

普通写作 Skill 大多集中于文字生成、改写和润色，而图片与内容结构之间的关联处理，可以形成明显差异化。

会建立一套内容视觉化分析机制。

## 4.1 自动识别插图需求

不是每个段落都需要配图，而是根据内容的表达属性判断。

| 内容类型 | 推荐视觉表达    |
| ---- | --------- |
| 抽象概念 | 概念示意图     |
| 技术原理 | 原理图、流程图   |
| 系统架构 | 架构图、组件关系图 |
| 操作步骤 | 步骤图、操作截图  |
| 数据对比 | 图表、对比表    |
| 场景描述 | 场景插画、实景照片 |
| 复杂过程 | 时序图、状态转换图 |

## 4.2 图片插入应该输出结构化结果

建议不要仅仅返回一段图片 Prompt，而是输出可以直接执行的插图计划。

这会让天工具备更强的可组合性。

这里还可以和之前设计的「格物 · Gewu」形成协作：

- 天工负责判断文章哪里需要图、需要什么图。
- 格物负责分析技术原理，提炼可视化表达方案。
- 天工负责将生成的图整合进文章。

这样就不是两个重复的 Skill，而是具有明确职责边界的协作体系。

# 五、写作提示系统：不要让 AI 直接替代作者

这是我认为天工最值得设计好的一个部分。

很多 AI 写作工具的缺点是：用户提供一个主题，直接生成几千字文章。

这种方式虽然效率高，但很容易造成内容空洞、观点趋同、缺乏个人思考。

建议天工设计一个动态写作提示机制（Writing Guidance）。

例如，用户正在写：

> Redis 的字典采用渐进式 Rehash 机制，在扩容期间逐步迁移数据。

天工不应该直接把后面几段全部写出来，而应该适时提示：

天工 · 写作建议

当前段落

这里可以进一步展开三个问题：

1. 为什么 Redis 不直接一次性迁移所有数据？
2. 如果一次性迁移，可能造成多长时间的阻塞？
3. 渐进式 Rehash 是如何在正常操作中完成数据迁移的？

推荐展开方式

- 先解释一次性迁移的性能问题。
- 再介绍渐进式迁移的基本思想。
- 最后通过一次查询或写入操作说明迁移过程。

建议补充的内容

- rehashidx 的作用。
- 迁移过程中增删改查如何处理。
- 渐进式迁移的优点与代价。

将提示分成四类：

- 引导型：告诉作者接下来应该写什么。
- 追问型：通过问题帮助作者深入思考。
- 补充型：提醒缺少的案例、论据和知识点。
- 纠错型：指出逻辑不完整、表达不准确的问题。

这比单纯的文本续写更有价值。

## 6.1 SKILL.md 的职责

入口文件应该尽可能精简，主要负责：

1. 描述 Skill 的定位和适用场景。
2. 判断用户当前的写作任务。
3. 识别当前写作阶段。
4. 选择对应的工作流。
5. 加载必要的参考文档和模板。
6. 约束输出格式与质量标准。

具体写作方法、评审标准和模板放在独立文件中，按需加载。

## 6.2 能力调用原则

区分三类能力：

| 能力类型             | 实现方式          |
| ---------------- | ------------- |
| 写作规划、结构分析        | LLM 推理        |
| 内容评审、表达优化        | LLM 推理        |
| 图片生成、素材搜索        | 外部工具或其他 Skill |
| SVG、Mermaid 图表   | 专项图形生成能力      |
| Markdown、HTML 转换 | 脚本或工具         |
| 事实核查、资料检索        | 搜索工具或研究 Skill |

不建议将所有能力都依赖大模型一次性完成。

特别是图片生成、资料检索、格式转换等，应该在需要时调用专门工具。

# 七、质量评审体系

天工不能仅仅以「文章写得通顺」作为完成标准。

建议设计六个评审维度：

| 评审维度 | 核心问题                |
| ---- | ------------------- |
| 完整性  | 是否覆盖了主题所需要的关键内容？    |
| 结构性  | 章节之间是否有清晰的组织关系？     |
| 逻辑性  | 论点、论据、结论是否成立？       |
| 准确性  | 技术、事实、数据是否准确？       |
| 可读性  | 是否容易理解，是否存在冗余？      |
| 表现力  | 是否恰当地运用了案例、图表和视觉元素？ |

可以采用分级结果：

- P0：严重问题，影响内容正确性。
- P1：重要问题，影响结构和逻辑。
- P2：一般问题，影响表达和可读性。
- P3：优化建议，提升阅读体验。

同时应该遵守一个原则：评审和修改分离。

用户要求评审时，先输出问题和修改建议；用户同意或明确要求修改后，再执行修改。避免 AI 擅自改变作者原本的观点。

# 九、与其他 Skill 的协作体系

我建议把天工放在整个内容生产体系的上层，负责内容组织与创作，而不是把所有专业能力都塞进去。

# 天工 · Tiangong

内容创作与组织中心

构思 · 规划 · 写作 · 编辑 · 排版

格物 · Gewu（直接拷贝获取文章编辑、图片插入等能力，Gewu-skill 后期的形态更强调解读而不是写作，编辑能力会逐渐去掉）

技术原理提取、知识图解

研究 / 爬虫 Skill

资料检索、信息收集

图片生成 Skill

插画、配图、封面

图表生成能力

SVG、Mermaid、数据图表

例如，完成一篇技术文章时：

1. 研究 Skill 收集相关资料。
2. 天工规划文章结构。
3. 天工撰写并持续提供写作提示。
4. 格物提取技术原理并生成图解方案。
5. 图片 Skill 生成封面和配图。
6. 天工整合内容、评审和排版。

这样就能形成一个可扩展的内容创作工作流。

# 十、关键补充

1\. 天工不是纯粹的文章生成器。

文章生成只是其中一个能力。真正有价值的是辅助作者思考、组织内容、发现问题和改善表达。

2\. 优先做好增量式协作写作。

用户可以随时提供一段文字，让天工分析、提出建议、补充内容，而不必每次都重新生成整篇文章。

3\. 图片应该成为一等能力。

不仅生成图片，还要理解图片在文章中的作用、位置、表达目标，以及与上下文的关系。

4\. 保留作者的表达风格。

不应该把所有文章都改成标准化的 AI 写作风格。尤其是技术博客，要尽量保留作者自己的观点、技术判断和表达习惯。

5\. 强调可验证性。

对于技术文章、知识文章，不能为了让内容完整而编造技术细节、数据和参考资料。需要区分已验证事实、合理推断和待确认信息。

## 最终：确定产品设计原则

天工的核心设计理念：

# 天工 · Tiangong

辅助创作，而非替代创作。

以作者的想法为起点，以内容结构为骨架，以写作指导为过程，以视觉表达为延伸，以质量评审为保障。

让 AI 成为作者的协作者，而不是内容的替代生产者。
